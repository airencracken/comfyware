# Comfyware audit: September 29, 2026

The review covered the four repositories in the Comfyware workspace: Imvault,
Witmoot, the Gentoo overlay, and the public website. Default branches were pulled
before review, and fixes were made in separate worktrees.

Starting revisions: Imvault `ff69d6a`, Witmoot `7a2cba7`, overlay `c5d8321`,
website `0e47091`. The application updates are Imvault 0.10.1 and Witmoot 0.7.3.

## Findings and fixes

| Area | Finding | Result |
| --- | --- | --- |
| Imvault authentication | A reset link or OIDC assertion granted a full session even when the local account required two-factor authentication. | Both routes continue to the code prompt; a TOTP or recovery code must complete sign-in. |
| Imvault recovery | Reset links issued before a password change could still replace the new password. | Password changes revoke outstanding reset and pending-sign-in tokens. |
| Imvault atomicity | A database failure could change the password without revoking sessions, or spend a reset link without updating the password. | Credential update, session/token revocation, and reset redemption share a transaction. |
| Imvault administration | Disabled administrators counted toward the last-administrator guard; concurrent removals checked and wrote separately. | Disabling, demotion, and deletion preserve one enabled administrator transactionally. |
| Imvault mail | STARTTLS silently fell back to plaintext when the relay did not advertise TLS. | STARTTLS is required unless the operator explicitly chooses another mode. |
| Imvault mail | Timeouts started after the relay greeting; silent greeting and implicit TLS connections could stall. | Timeout and cancellation cover connection, handshake, greeting, and delivery. |
| Imvault mail | Both message preparation and SMTP escaped leading dots. | Only the SMTP transport escapes them, preserving the recipient's text. |
| Imvault installation | OpenRC configuration containing SMTP credentials was installed as mode 0644. | Source, Alpine, and Gentoo installs use mode 0600. Source reinstall preserves local values and tightens regular files. |
| Witmoot installation | OpenRC omitted SMTP settings from the daemon's environment. | All six documented settings are exported, including plain assignments in conf.d. |
| Witmoot test isolation | Repeated offline tests intermittently left a speculative HTTP connection open, exceeding the demo shutdown deadline. | Each test reader owns its transport and closes idle connections before shutdown; twenty consecutive demo checks passed. |
| Overlay publication | A dependency bundle created by a competing process could be overwritten after the initial existence check. | Staging stays on the destination filesystem and an exclusive hard link publishes the completed bundle. Existing files and dangling symlinks are preserved. |
| Overlay runtime dependencies | Imvault did not require the system CA bundle needed for S3, OIDC, and encrypted SMTP on a minimal host. | Imvault recipes now depend on ca-certificates; staged installation checks enforce this requirement for both apps. |

The authentication, transaction, administrator, SMTP, installation, and
publication defects were reproduced against the starting code before fixing
them. The regressions remain in the normal test suites.

## Refinement

- Imvault's second-factor prompt no longer says a password was accepted when the
  user authenticated through OIDC.
- Witmoot uses “Sign in” consistently for sign-in controls. Redundant footer and
  sidebar slogans were trimmed, and reply guidance describes what users need.
- Witmoot's README now describes existing board creation, permissions, and
  archiving instead of calling room management future work.
- The website uses descriptive feature headings and clearer primary navigation.
  It distinguishes existing Imvault moderation from Witmoot's limited tools.
- The Witmoot demo screenshot was refreshed in both the app and website.

## Validation

Both apps passed their required local checks: vet, formatting, JavaScript tests,
and complete Go race suites. Imvault also passed its complexity check and 65
browser assertions. Witmoot's browser workflows covered authentication, posting,
search, invitations, all site modes, board/group permissions, edits, archives,
restoration, and confirmed deletion, with and without JavaScript. Real Imvault
API integration passed in both browser modes.

New regressions cover real HTTP authentication flows, successful second-factor
completion, expired recovery after a password change, database failure injection
at each write, concurrent reset redemption, concurrent administrator removal,
SMTP wire text and transport boundaries, environment propagation, staged
permissions, and competing bundle publication. Existing schema, API, route,
adversarial-input, and mutation checks were included in the full suites.

The website passed content and link contracts, deliberate markup mutations,
production HTTP routes/headers/traversal/method checks, Caddy validation, and 248
browser checks covering two themes, four widths, accessibility, theme storage,
and navigation without JavaScript. Desktop and mobile screenshots were inspected.

The release workflows require artifact verification, nginx/Apache integration,
and Debian/Ubuntu package lifecycle tests on amd64 and arm64 before publishing.
nginx and Apache were unavailable locally; their checks run in that pipeline.
Gentoo installation is checked in an unprivileged staging directory and by the
overlay QA workflow. A full emerge was not run on this development host.

The offline pass caught the demo test failure after 0.7.2 had passed its release
gates and published. The source-test correction is released as 0.7.3; installed
application behavior is unchanged from 0.7.2. Both final versions were built
and tested using verified dependency bundles with Go module networking disabled.

## Upgrade details

No database migrations are added. Imvault users with an enabled factor now need
it for recovery and provider sign-in. An intentionally plaintext local mail
relay needs `IMVAULT_SMTP_TLS=none`. Existing OpenRC operators should check
configuration permissions and replace SMTP credentials previously exposed to
other local users. Changing a password after upgrading revokes sessions and
reset attempts created by older versions; upgrading alone does not revoke them.

Witmoot operators should update the OpenRC service script and restart the
service. Existing data and configuration values are preserved.

The website repository has checks but no automatic production deployment.
Its public files can be deployed once the hosting destination is supplied.
